## 1. В чём биологическая и физическая проблема?

Обычные модели машинного обучения принимают на вход строку с текущими числами:
$$\text{Строка: [Дата: 21 июля, Температура сегодня: } 26^\circ\text{C, Ветер: } 1.5\text{ м/с]}$$

Если скормить модели только эти мгновенные значения, **она не сможет предсказать цветение**.  
Почему? Потому что озеро обладает колоссальной **тепловой и экологической инерцией**:
1. Вода в озере Нарочь или Минском море не нагревается за один день. Чтобы фитопланктон начал бурно делиться, толща воды должна прогреваться **10–14 дней подряд**.
2. Всплытие колоний цианобактерий на поверхность происходит только при **штиле** (скорость ветра $< 2.2\text{ м/с}$) на протяжении нескольких дней подряд.
3. Биогенные элементы (фосфор и азот) попадают в водоём не сами по себе — их смывают ливневые дожди с полей водосбора за **5–10 дней до вспышки цветения**.

> **Вывод:** Модель должна «видеть» не только сегодняшний день, но и **накопленную предысторию**. Процесс создания таких математических индикаторов называется **Feature Engineering** (конструирование признаков).

## 2. Скользящие оконные функции в Pandas (`.rolling()`)

Метод `.rolling(window=N)` создаёт «окно» фиксированного размера $N$, которое скользит по временному ряду, рассчитывая агрегатные статистики для каждой точки.

### 2.1. Скользящее среднее (Moving Average)
Рассчитывает среднюю температуру за последние 14 дней:
```python
import pandas as pd

# 14-дневное скользящее среднее температуры воздуха
df["temp_mean_14d"] = df["T2M"].rolling(window=14, min_periods=1).mean()
```
*Параметр `min_periods=1`:* позволяет не терять данные в первые 13 дней года, рассчитывая среднее по фактически доступному количеству дней.

### 2.2. Скользящая сумма (Cumulative Sum)
Рассчитывает суммарное количество осадков (смыв биогенов с водосбора за неделю):
```python
# Сумма осадков за последние 7 дней (мм)
df["precip_sum_7d"] = df["PRECTOTCORR"].rolling(window=7, min_periods=1).sum()
```

### 2.3. Доля штилевых дней (Штилевой триггер)
Цианобактерии всплывают к поверхности, только когда нет ветрового перемешивания (ветер $< 2.2\text{ м/с}$):
```python
# Булев флаг штиля (True/False)
is_calm = df["WS2M"] < 2.2

# Доля дней со штилем за последние 7 дней (число от 0.0 до 1.0)
df["calm_fraction_7d"] = is_calm.rolling(window=7, min_periods=1).mean()
```

## 3. Временные лаги (Lags & Shifts)

Лаг — это значение целевой переменной или фактора $N$ шагов назад во времени.

В задачах качества воды концентрация хлорофилла обладает высокой автокорреляцией: если 10 дней назад хлорофилла было много, то сегодня он с высокой вероятностью тоже высок.

```python
# Значение концентрации хлорофилла 10 дней назад:
df["chl_a_lag10d"] = df["chl_a"].shift(1)

# Скорость изменения (прирост биомассы фитопланктона за 10 дней):
df["chl_a_growth"] = df["chl_a"] - df["chl_a_lag10d"]
```

## 4. Циклическое кодирование сезонов (`sin` / `cos`)

В календаре 365 дней. Но если подать в модель машинного обучения день года просто как число от 1 до 365:
* 31 декабря — это день №365.
* 1 января — это день №1.
* Чисто математически расстояние между ними: $|365 - 1| = 364$!  
  Модель решит, что 31 декабря и 1 января — это две противоположные крайности, хотя на самом деле это **соседние дни одной и той же зимы**!

Чтобы замкнуть календарный год в кольцо, применяют тригонометрическое преобразование:
```python
import numpy as np

doy = df["date"].dt.dayofyear  # 1..365

# Кодирование в единичную окружность
df["sin_doy"] = np.sin(2 * np.pi * doy / 365.25)
df["cos_doy"] = np.cos(2 * np.pi * doy / 365.25)
```
Теперь 31 декабря и 1 января находятся в пространстве признаков **вплотную друг к другу**!

## 5. Как это реализовано в НАШЕМ курсовом проекте?

В файле `water_eutrophication/src/features/build_features.py` генерируется витрина из 28 признаков:
```python
# Скользящие тепловые факторы
temp_mean_7d = m_window_7["T2M"].mean()
temp_mean_14d = m_window_14["T2M"].mean()
temp_mean_21d = m_window_21["T2M"].mean()

# Подсчет аномально жарких дней за 2 недели
hot_days_14d = (m_window_14["T2M_MAX"] >= 22.0).sum()

# Накопление осадков и радиации
precip_sum_7d = m_window_7["PRECTOTCORR"].sum()
radiation_mean_7d = m_window_7["ALLSKY_SFC_SW_DWN"].mean()
```
Именно эти агрегированные признаки позволяют модели LightGBM прогнозировать цветение с точностью $R^2 = 0.880$!
