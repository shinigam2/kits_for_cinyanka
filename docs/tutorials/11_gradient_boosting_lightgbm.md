## 1. Почему не нейросети? Миф о «глубоком обучении»

Многие начинающие программисты считают: *«Если проект сложный — нужно обязательно брать нейросеть (PyTorch / TensorFlow)»*.

В науке о данных есть строго доказанный факт:
* **Нейросети** доминируют в задачах с однородными данными: изображения (пиксели), звук (аудиоволны), тексты (токены).
* На **табличных данных** (гетерогенные признаки: температура, влажность, радиация, глубина, даты) алгоритмы **градиентного бустинга на деревьях решений (GBDT)** стабильно превосходят нейросети по качеству, обучаются в 50 раз быстрее и не требуют долгого подбора архитектуры!

В чемпионатах по машинному обучению (Kaggle) 80% победных решений на таблицах строятся именно на **LightGBM**.

## 2. Эволюция: от одного дерева к градиентному бустингу

### Шаг 1. Одно дерево решений (Decision Tree)
Дерево решений — это цепочка условий «если-то» (if-else):
$$\text{Если } T_{max} > 22^\circ\text{C} \longrightarrow \text{Если Ветер } < 2.2\text{ м/с} \longrightarrow \text{Прогноз: Цветение}$$
*Проблема:* Одно дерево либо слишком простое (недообучение), либо слишком глубокое и запоминает шум (переобучение).

### Шаг 2. Случайный лес (Random Forest / Бэггинг)
Мы обучаем 100 независимых деревьев параллельно на случайных подвыборках данных и усредняем их ответы.
*Плюс:* Устойчивость.  
*Минус:* Деревья не учатся друг у друга.

### Шаг 3. Градиентный бустинг (Gradient Boosting)
В бустинге деревья строятся **последовательно, в цепочку**:
1. Дерево №1 делает первое грубое предсказание.
2. Мы вычисляем его ошибки (остатки, **Residuals**): где именно дерево ошиблось?
3. Дерево №2 обучается **не на исходные ответы, а на ошибки первого дерева**, чтобы исправить их!
4. Дерево №3 обучается на остаточные ошибки деревьев №1 и №2.
5. Итоговый прогноз — это взвешенная сумма всех деревьев в ансамбле:
   $$\hat{y} = \text{Tree}_1(X) + \eta \cdot \text{Tree}_2(X) + \eta \cdot \text{Tree}_3(X) + \dots$$
   *(где $\eta$ — learning rate, скорость обучения, например $0.05$).*

## 3. Почему именно LightGBM (разработка Microsoft)?

Классический бустинг (например, ранний XGBoost) был медленным, потому что при каждом делении перебирал все возможные пороги для каждого вещественного числа.

**LightGBM (Light Gradient Boosting Machine)** совершил революцию благодаря двум инженерным решениям:
1. **Гистограммный метод (Histogram-based Binning):**  
   Непрерывные числа (температуры $21.345^\circ\text{C}$, $21.348^\circ\text{C}$) группируются в 256 дискретных «корзин» (bins). Это ускоряет вычисления в **15–20 раз** и радикально экономит оперативную память.
2. **Рост деревьев «по листьям» (Leaf-wise):**  
   Вместо того чтобы равномерно растить дерево слой за слоем (как в XGBoost), LightGBM на каждом шаге делит тот единственный лист, который даст максимальное снижение ошибки.

## 4. Важность признаков (Feature Importance)

Одно из главных преимуществ бустинга — **интерпретируемость**. Модель может сама ранжировать физические факторы по степени влияния на целевую переменную.

В нашем проекте алгоритм выделил топ-5 драйверов цветения:
1. `turbidity_current` (текущая мутность воды) — 142 сплита;
2. `cos_doy` (сезонный календарный цикл) — 112 сплитов;
3. `radiation_mean_7d` (инсоляция за 7 дней) — 90 сплитов;
4. `chl_a_current` (исходный уровень хлорофилла) — 73 сплита;
5. `temp_max_7d` (пиковая жара за неделю) — 57 сплитов.

## 5. Как это реализовано в НАШЕМ курсовом проекте?

В файле `water_eutrophication/src/models/train_models.py`:

```python
import lightgbm as lgb

# 1. Регрессор для численного хлорофилла:
lgb_reg = lgb.LGBMRegressor(
    n_estimators=120,      # Количество последовательных деревьев
    learning_rate=0.04,    # Скорость обучения каждого дерева
    max_depth=5,           # Максимальная глубина дерева (защита от переобучения)
    num_leaves=18,         # Максимум листьев в одном дереве
    random_state=42,
    verbose=-1
)
lgb_reg.fit(X_train, y_train)

# 2. Классификатор для риска цветения:
lgb_clf = lgb.LGBMClassifier(
    n_estimators=100,
    learning_rate=0.05,
    class_weight="balanced", # Автоматически компенсирует редкость событий цветения!
    random_state=42,
    verbose=-1
)
lgb_clf.fit(X_train, y_train_bloom)
```
