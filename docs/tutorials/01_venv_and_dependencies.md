## 1. В чём проблема и почему нельзя ставить библиотеки глобально?

Когда вы только начинаете работать с Python, самый частый способ установки библиотек — написать в консоли:
```bash
pip install pandas
```
В маленьких учебных скриптах это работает. Но в любом реальном проекте это приводит к катастрофе по трём причинам:

1. **Конфликт версий между проектами:**
   * Проект А (наш курсовой по экологии) использует `lightgbm==4.3.0` и `pandas==2.2.0`.
   * Проект Б (например, веб-парсер или Telegram-бот) написан год назад и работает только со старым `pandas==1.5.0`.
   * Если библиотека одна на всю операционную систему, обновление для одного проекта **безвозвратно сломает другой**.
2. **Безопасность системы (особенно в Linux):**
   * В Ubuntu, Debian, Fedora и других Linux системный Python используется самой ОС для обновления пакетов и системных утилит. Засорение системного Python сторонними `pip`-пакетами может нарушить работу операционной системы.
3. **Проблема воспроизводимости («У меня всё работает, а у преподавателя падает с ошибкой»):**
   * Чтобы проект запустился на сервере, в облаке или на компьютере преподавателя, нужен строгий, зафиксированный список точных версий всех используемых библиотек.

## 2. Что такое `.venv` под капотом?

Многие думают, что виртуальное окружение — это какая-то виртуальная машина или сложный контейнер. **Нет! Это просто обычная папка на диске.**

Когда вы выполняете команду:
```bash
python3 -m venv .venv
```
Python выполняет простейшую последовательность действий:
1. Создаёт папку `.venv/` в текущей директории.
2. Внутрь кладёт симлинк (ярлык) на системный интерпретатор: `.venv/bin/python`.
3. Создаёт чистую локальную папку для сторонних библиотек:  
   `.venv/lib/python3.12/site-packages/`
4. Копирует локальный менеджер пакетов: `.venv/bin/pip`.
5. Создаёт конфигурационный файл: `.venv/pyvenv.cfg`.

> **Главный вывод:** Когда вы устанавливаете библиотеку в виртуальное окружение, файлы физически скачиваются в папку `.venv/lib/python3.12/site-packages/`. Ваша операционная система остаётся чистой!

## 3. Два способа работы с `.venv`

### Способ 1. Интерактивный (через активацию терминала)
Используется разработчиком при ручной работе в консоли:

```bash
# 1. Создание (один раз в начале работы над проектом)
python3 -m venv .venv

# 2. Активация
source .venv/bin/activate
```

После этого в начале строки консоли появляется метка: `(.venv) user@pc:~$`.  
Что делает скрипт `activate`? Он просто временно меняет системную переменную `$PATH` в текущем окне терминала, чтобы команды `python` и `pip` указывали на файлы внутри папки `.venv/bin/`.

Теперь можно работать привычно:
```bash
pip install requests
python main.py
```
Чтобы выйти из окружения:
```bash
deactivate
```

---

### Способ 2. Профессиональный (прямой вызов бинарников)
Используется в серверах, скриптах автоматизации, cron-задачах и Docker:

```bash
# Установка библиотеки в конкретное окружение напрямую:
.venv/bin/pip install requests

# Запуск скрипта напрямую нужным интерпретатором:
.venv/bin/python main.py
```

*Плюс этого подхода:* Вы на 100% застрахованы от ситуации, когда забыли активировать окружение или в системе перепутались переменные путей.

## 4. Фиксация зависимостей (`requirements.txt`)

Папку `.venv` **никогда не коммитят в Git** (она весит сотни мегабайт и привязана к конкретной версии ОС). В файле `.gitignore` всегда первой строчкой пишут `.venv/`.

Вместо этого передают текстовый файл **`requirements.txt`**.

### Как сохранить зависимости текущего проекта:
```bash
.venv/bin/pip freeze > requirements.txt
```
В файле сохраняется точный список установленных библиотек:
```text
lightgbm==4.7.0
pandas==2.2.0
pyarrow==25.0.1
requests==2.34.2
```

### Как восстановить окружение с нуля на новой машине:
```bash
# Шаг 1. Создать чистое окружение
python3 -m venv .venv

# Шаг 2. Установить все зависимости одной командой
.venv/bin/pip install -r requirements.txt
```

## 5. Памятка частых ошибок
* ❌ Забыть добавить `.venv/` в `.gitignore` $\rightarrow$ Git пытается закоммитить 50 000 чужих файлов библиотек.
* ❌ Запустить `pip install` глобально вместо `.venv/bin/pip` $\rightarrow$ пакет поставится мимо проекта, проект не найдёт библиотеку (`ModuleNotFoundError`).
* ❌ Удалить код проекта вместо `.venv` $\rightarrow$ всегда проверяйте, какую папку удаляете. Код лежит в `src/`, а библиотеки — в `.venv/`.
