## 1. В чём проблема и почему не обычные переменные в Python?

В простых учебных скриптах параметры обычно «зашивают» прямо в исходный код (хардкод):
```python
# ПЛОХО: жесткий хардкод в теле программы
lake_name = "Заславское водохранилище"
lat = 53.9850
lon = 27.3800
bloom_threshold = 25.0
```

Почему в промышленной разработке так **не делают**:
1. **Нарушение принципа разделения кода и настроек (The Twelve-Factor App):**  
   Алгоритм должен быть универсальным, а входные параметры — вынесены наружу.
2. **Риск сломать работающую программу:**  
   Если специалисту-экологу нужно добавить новое озеро (например, Нарочь или Лукомльское), ему не нужно лезть в алгоритмы расчета и рисковать поставить лишнюю скобку или отступ в Python-файле. Он просто добавляет блок текста в конфигурационный файл.
3. **Универсальность:**  
   Конфигурационный файл могут читать микросервисы на разных языках (Python, Go, Java, фронтенд на JS).

## 2. Синтаксис языка YAML (Шпаргалка)

* **Ключ и значение:** отделяются двоеточием с обязательным пробелом (`name: "Озеро"`).
* **Отступы:** **только пробелы** (строго 2 пробела на уровень). Использовать клавишу `Tab` запрещено!
* **Списки:** дефис и пробел (`- "фактор 1"`). Все дефисы одного списка должны быть строго на одной вертикальной линии.
* **Комментарии:** символ `#`.

## 3. Как именно YAML используется в НАШЕМ курсовом проекте?

Вся конфигурационная логика нашего проекта вынесена в единый файл:  
📂 `water_eutrophication/configs/water_bodies.yaml`

Давайте посмотрим, как разные Python-модули читают его на практике:

### Пример А. В модуле загрузки метеоданных (`src/data/download_meteo.py`)
Скрипт не знает заранее, какие координаты опрашивать у NASA. Он считывает их из YAML:
```python
import yaml
from pathlib import Path

# Загружаем конфиг
with open("configs/water_bodies.yaml", "r", encoding="utf-8") as f:
    config = yaml.safe_load(f)

# 1. Извлекаем временной диапазон проекта:
start_date = config["project"]["date_range"]["start_date"]  # "2020-01-01"
end_date = config["project"]["date_range"]["end_date"]      # "2025-12-31"

# 2. Итерируемся по всем водоемам Беларуси из конфига:
for key, wb_info in config["water_bodies"].items():
    lat = wb_info["coordinates"]["lat"]
    lon = wb_info["coordinates"]["lon"]
    name = wb_info["name_ru"]
    print(f"Отправка запроса к спутнику NASA для {name}: широта {lat}, долгота {lon}")
```
*Плюс подхода:* Чтобы начать мониторинг третьего озера (например, Лукомльского), мы **не меняем ни одной строчки в `download_meteo.py`**. Мы просто дописываем 6 строчек в `water_bodies.yaml`!

## 4. Где и как практиковаться (Самостоятельная практика)

Практиковать синтаксис YAML лучше всего не «вслепую», а с мгновенной обратной связью (валидацией):

### 1. Онлайн-тренажеры и валидаторы синтаксиса:
* **[YAML Lint (yamllint.com)](https://www.yamllint.com/)** — вставьте ваш текст, нажмите кнопку, и сервис подсветит точную строку, где нарушен отступ или потерян пробел.
* **[JSON to YAML Converter](https://json2yaml.com/)** — отличный способ увидеть, как один и тот же объект выглядит в JSON и в YAML.

### 2. Практика в вашей среде разработки (VS Code / PyCharm):
* Установите официальный плагин **"YAML" от Red Hat** в VS Code. Он автоматически подсвечивает синтаксические ошибки красным цветом и выравнивает отступы.

### 3. Задачи для самостоятельной тренировки:
1. **Задача на список словарей:** Напишите YAML-структуру с ключом `sensors`, содержащую список из 3 датчиков, у каждого из которых есть `id`, `type` ("temperature" / "turbidity") и `is_online` (true/false).
2. **Задача на вложенность:** Опишите конфигурацию базы данных PostgreSQL: `host`, `port`, `credentials` (внутри `username` и `password`), `database_name`.
3. **Проверка в Python:** Создайте локально файл `test.yaml`, напишите туда свои данные и прочитайте их однострочником:
   ```python
   import yaml; print(yaml.safe_load(open("test.yaml")))
   ```
