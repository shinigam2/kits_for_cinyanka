## 1. В чём проблема с привычным форматом CSV?

Начинающие аналитики почти всегда сохраняют все таблицы в текстовый формат CSV (`df.to_csv("data.csv")`).  
Для файлов на 500 строк это допустимо. Но в масштабных проектах у CSV есть **три критических недостатка**:

1. **CSV теряет типы данных:**
   * CSV — это обычный «тупой» текстовый файл. В нём всё записано просто буквами и цифрами через запятую.
   * Когда вы сохраняете столбец дат `2025-07-21` в CSV, он превращается в обычный текст. При следующем чтении файла вам снова придётся вручную писать `pd.to_datetime()`. Числа с плавающей точкой могут потерять точность из-за округления строк.
2. **CSV занимает огромный объём диска:**
   * Каждая цифра, буква и знак препинания хранятся отдельными байтами символов.
3. **CSV читается медленно (строчный построчный формат):**
   * Чтобы прочитать из CSV всего одну колонку (например, только `T2M`), компьютеру приходится считывать с диска **весь файл целиком от первой до последней строчки**, разбирая каждую запятую.

## 2. Что такое Apache Parquet и почему он победил CSV?

**Apache Parquet** — это открытый бинарный формат хранения данных, созданный инженерами Twitter и Cloudera специально для высоконагруженных вычислений, Big Data и машинного обучения.

### Главные преимущества Parquet:

1. **Колоночное хранение (Columnar Storage):**  
   Данные сохраняются не строчками, а целыми колонками. Если в вашей таблице 50 столбцов, а модели для прогноза нужны только `date` и `chl_a_ug_l`, Parquet считает с диска **только эти два столбца**, вообще не трогая остальные 48!
2. **Встроенное сжатие (Snappy / Gzip / ZSTD):**  
   Поскольку в одной колонке лежат однотипные данные (например, миллион чисел с плавающей точкой), алгоритм сжатия сжимает их колоссально эффективно — файл «весит» в **4–10 раз меньше**, чем аналогичный CSV.
3. **Сохранение точной схемы (Metadata & Schema):**  
   В заголовке и «подвале» (footer) файла Parquet сохраняется метаинформация о точных типах данных: `float64`, `int32`, `datetime64[ns]`. При чтении Pandas сразу получает готовые правильные типы.

## 3. Библиотека `pyarrow` в Python

Чтобы Pandas умел молниеносно читать и записывать файлы Parquet, используется высокопроизводительный движок на C++ — **Apache Arrow (`pyarrow`)**.

### Установка:
```bash
.venv/bin/pip install pyarrow
```

### Как работать в коде Python:

```python
import pandas as pd

# 1. Сохранение DataFrame в Parquet (индекс обычно отключают index=False):
df.to_parquet("weather_data.parquet", index=False)

# 2. Мгновенное чтение всего файла:
df = pd.read_parquet("weather_data.parquet")

# 3. Чтение ТОЛЬКО нужных колонок (колоссальная экономия памяти RAM и времени):
df_sub = pd.read_parquet("weather_data.parquet", columns=["date", "T2M", "WS2M"])
```

## 4. Сравнение на реальных данных НАШЕГО проекта

В нашем проекте метеорологические данные сохранены в двух форматах:
* CSV: `water_eutrophication/data/raw/meteo/zaslavskoye_daily_meteo.csv`
* Parquet: `water_eutrophication/data/processed/combined_meteo.parquet`

| Параметр сравнения | CSV | Apache Parquet |
| :--- | :---: | :---: |
| **Размер на диске** | $\sim 150\text{ Кб}$ | **$\sim 38\text{ Кб}$ (в 4 раза меньше!)** |
| **Скорость чтения в Pandas** | Базовая ($\sim 15\text{ мс}$) | **Мгновенно ($\sim 2-3\text{ мс}$)** |
| **Сохранение типов дат** | Теряется (становится `str`) | **Сохраняется (`datetime64`)** |
| **Выборочное чтение колонок** | Невозможно | **Встроено из коробки** |

## 5. Где и как практиковаться самостоятельно

1. **Локальный эксперимент на сравнение скорости и размера:**
   Возьмите любой большой CSV-файл (или наш датасет), сохраните его в Parquet и замерьте время:
   ```python
   import time
   import pandas as pd

   df = pd.read_csv("water_eutrophication/data/raw/meteo/zaslavskoye_daily_meteo.csv")
   df.to_parquet("test.parquet")

   # Сравните размер:
   import os
   print("CSV размер:", os.path.getsize("water_eutrophication/data/raw/meteo/zaslavskoye_daily_meteo.csv"))
   print("Parquet размер:", os.path.getsize("test.parquet"))
   ```
2. **Просмотр содержимого Parquet без Python:**
   Установите расширение **"Parquet Viewer"** для VS Code. Оно позволяет открывать бинарные `.parquet` файлы прямо в редакторе в виде интерактивной таблицы со страницами и сортировкой.
