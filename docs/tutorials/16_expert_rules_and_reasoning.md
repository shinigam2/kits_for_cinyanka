## 1. Зачем нужны экспертные правила, если у нас уже есть Machine Learning?

В предыдущих модулях мы обучили градиентный бустинг (LightGBM), который умеет с высокой точностью прогнозировать концентрацию хлорофилла-а и вероятность цветения:
- **ML выдаёт сухие числа:** например, $\text{Chl-a} = 34.5\ \text{мкг/л}$, а вероятность цветения $P(\text{Bloom}) = 0.88$.

Однако представьте, что эта система передаётся в государственные органы: **Министерство природных ресурсов и охраны окружающей среды Республики Беларусь (Минприроды РБ)** или **Республиканский центр гигиены, эпидемиологии и общественного здоровья**.

Если инспектор санэпиднадзора закроет пляж на Заславском водохранилище (Минском море) со словами:
> *«Пляж закрыт, потому что библиотека LightGBM в Python выдала число 0.88»*,

то это решение не выдержит никакой юридической и нормативной критики. В практической экологии и медицине модели машинного обучения часто называют **«чёрными ящиками» (Black Box)**: они находят сложные корреляции, но не могут сослаться на нормативный регламент или объяснить свои выводы на человеческом языке.

Для преодоления этой проблемы применяется концепция **Explainable AI (XAI — объяснимый искусственный интеллект)** и **Гибридный ИИ (Neuro-Symbolic AI)**:
1. **Машинное обучение (Machine Learning)** выполняет расчёт прогнозов на основе больших массивов сырых данных (спутники, метеостанции).
2. **Символьный ИИ и экспертные правила (Symbolic AI & Expert Rules)** берут этот прогноз, сопоставляют его с нормативно-правовой базой (СанПиН РБ) и знаниями гидроэкологии, после чего формируют **юридически обоснованное и понятное человеку экспертное заключение**.

## 2. Что такое продукционные правила (Production Rules)?

**Продукционная модель** — это классический и самый наглядный способ представления человеческих знаний в компьютерных системах.

Правило строится по принципу:
$$\text{ЕСЛИ } \langle \text{Условие / Антецедент} \rangle \longrightarrow \text{ТО } \langle \text{Заключение / Рекомендация / Консеквент} \rangle$$

### Примеры правил в нашей системе:
* **Правило 1 (Критический риск):**
  - **ЕСЛИ** $\text{Chl-a} \ge 25\ \text{мкг/л}$ **ИЛИ** $P(\text{Bloom}) \ge 0.50$,
  - **ТО** Уровень тревоги = `RED`, выдать обоснование о превышении санитарного порога и рекомендацию ограничить рекреационное водопользование.
* **Правило 2 (Благоприятствующие метеоусловия):**
  - **ЕСЛИ** Уровень тревоги = `RED` **И** средняя температура за 14 дней $> 18^\circ\text{C}$ **И** доля штилевых дней за неделю $> 40\%$,
  - **ТО** Добавить в отчёт объяснение: *«Штиль и термический прогрев стимулируют концентрацию токсичных цианобактерий в поверхностном слое воды»*.
* **Правило 3 (Умеренный риск / Внимание):**
  - **ЕСЛИ** $15 \le \text{Chl-a} < 25\ \text{мкг/л}$ **ИЛИ** ($\text{T}_{\text{14d}} \ge 20^\circ\text{C}$ **И** $\text{штиль}_{\text{7d}} \ge 30\%$),
  - **ТО** Уровень тревоги = `YELLOW`, рекомендация: провести экспресс-замер растворенного кислорода и увеличить частоту спутниковых съёмок Sentinel-2.

## 3. Нормативная база Беларуси и классификация Карлсона

В курсовом проекте экспертные правила базируются на реальных научно-практических стандартах:

1. **Санитарные нормы и правила Беларуси (СанПиН РБ):**
   - Гигиенические нормативы содержания биогенных и органических веществ в водных объектах, используемых для рекреации (купания, водных видов спорта).
   - Порог $\text{Chl-a} = 25\ \text{мкг/л}$ разделяет умеренную эвтрофикацию от вспышки сине-зеленых водорослей (цианобактерий рода *Microcystis*, *Anabaena*), способных выделять гепатотоксины (микроцистины).
2. **Индекс трофического состояния Карлсона (TSI):**
   - $\text{TSI} < 40$ — Олиготрофный (чистая, прозрачная вода, пример: озеро Нарочь);
   - $40 \le \text{TSI} < 50$ — Мезотрофный (умеренная продуктивность);
   - $50 \le \text{TSI} \le 70$ — Эвтрофный (высокая продуктивность, характерно для Заславского водохранилища летом);
   - $\text{TSI} > 70$ — Гиперэвтрофный (критическое цветение, дефицит кислорода, замор рыбы).

## 4. Реализация экспертного вывода в проекте (`graph_engine.py`)

В нашем проекте файл [`src/knowledge_graph/graph_engine.py`](file:///home/frolov-pc/antigravity/water_eutrophication/src/knowledge_graph/graph_engine.py) объединяет:
1. Вычисление трофического класса Карлсона.
2. Продукционный механизм вывода правил риска.
3. Сохранение логических выводов в виде триплетов в RDF-граф знаний.
4. Предоставление понятного вердикта `AlertVerdict`.

### Упрощённый пример работы экспертного механизма:

```python
import math
from dataclasses import dataclass
from typing import List

@dataclass
class AlertVerdict:
    water_body_name: str
    predicted_chl_a: float
    bloom_probability: float
    trophic_class: str
    alert_level: str  # GREEN, YELLOW, RED
    reasons: List[str]
    recommended_actions: List[str]


def evaluate_risk(
    water_body_name: str,
    predicted_chl_a: float,
    bloom_prob: float,
    temp_mean_14d: float,
    calm_fraction_7d: float
) -> AlertVerdict:
    # 1. Расчёт трофического класса по Карлсону
    tsi = round(9.81 * math.log(max(0.1, predicted_chl_a)) + 30.6, 1)
    if tsi < 40:
        trophic_class = "Олиготрофный"
    elif tsi < 50:
        trophic_class = "Мезотрофный"
    elif tsi <= 70:
        trophic_class = "Эвтрофный"
    else:
        trophic_class = "Гиперэвтрофный (Критический)"

    reasons = []
    actions = []

    # 2. Правила логического вывода (СанПиН РБ)
    if predicted_chl_a >= 25.0 or bloom_prob >= 0.50:
        alert_level = "RED"
        reasons.append(
            f"Прогнозируемый хлорофилл-a ({predicted_chl_a:.1f} мкг/л) "
            f"превышает порог эвтрофикации СанПиН РБ (25 мкг/л)."
        )
        reasons.append(f"Модельная вероятность цветения цианобактерий: {bloom_prob * 100:.1f}%.")
        
        if calm_fraction_7d > 0.4:
            reasons.append(f"Штиль ({calm_fraction_7d * 100:.0f}% безветренных дней) концентрирует водоросли у поверхности.")
        if temp_mean_14d > 18.0:
            reasons.append(f"Прогрев воды ({temp_mean_14d:.1f}°C за 14 дней) ускоряет биологическую вегетацию.")

        actions.append("Усилить лабораторный контроль: отбор проб на микроцистины.")
        actions.append("Уведомить территориальные органы Минприроды и санэпиднадзора.")
        actions.append("Рекомендовать временное ограничение купания в зонах отдыха.")

    elif predicted_chl_a >= 15.0 or (temp_mean_14d >= 20.0 and calm_fraction_7d >= 0.3):
        alert_level = "YELLOW"
        reasons.append(f"Повышенная концентрация хлорофилла-a ({predicted_chl_a:.1f} мкг/л) с тенденцией к росту.")
        actions.append("Увеличить частоту спутникового мониторинга Sentinel-2.")
        actions.append("Провести замер растворенного кислорода на контрольных станциях.")
    else:
        alert_level = "GREEN"
        reasons.append(f"Показатели в норме (Chl-a = {predicted_chl_a:.1f} мкг/л, статус: {trophic_class}).")
        actions.append("Продолжить плановый фоновый гидромониторинг.")

    return AlertVerdict(
        water_body_name=water_body_name,
        predicted_chl_a=predicted_chl_a,
        bloom_probability=bloom_prob,
        trophic_class=trophic_class,
        alert_level=alert_level,
        reasons=reasons,
        recommended_actions=actions,
    )
```

## 5. Как результат вывода сохраняется в RDF-граф и запрашивается через SPARQL

Когда правило срабатывает, движок не просто возвращает текст — он создаёт семантические триплеты и связывает их с сущностью водоёма:

```python
# Создаем узел предупреждения в онтологии
alert_uri = URIRef(f"http://w3id.org/belarus/water-quality#Alert_{water_body_id}_{date}")
graph.add((alert_uri, RDF.type, BYWATER.EarlyWarningAlert))
graph.add((alert_uri, BYWATER.alertLevel, Literal(alert_level, datatype=XSD.string)))
graph.add((alert_uri, BYWATER.explanationReason, Literal(" | ".join(reasons), datatype=XSD.string)))
graph.add((alert_uri, BYWATER.recommendedAction, Literal(" | ".join(actions), datatype=XSD.string)))
```

Затем внешние потребители (веб-интерфейс, мобильное приложение инспектора) могут выполнить стандартный SPARQL-запрос:
```sparql
PREFIX bywater: <http://w3id.org/belarus/water-quality#>

SELECT ?wbName ?level ?reason ?action
WHERE {
    ?alert a bywater:EarlyWarningAlert ;
           bywater:alertLevel ?level ;
           bywater:explanationReason ?reason ;
           bywater:recommendedAction ?action .
    FILTER (?level = "RED")
}
```
Такой подход гарантирует, что система не просто «угадывает», а предоставляет строгую доказательную цепочку: **Данные $\rightarrow$ ML-прогноз $\rightarrow$ Онтология $\rightarrow$ Правила СанПиН $\rightarrow$ Рекомендации**.
