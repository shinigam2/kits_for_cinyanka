# Технология №18: Uvicorn и стандарт ASGI (Асинхронный веб-сервер для FastAPI)

---

## 1. Зачем нужен отдельный веб-сервер, если у нас уже написан FastAPI?

Частая ошибка новичков — путать **веб-фреймворк** (FastAPI, Flask, Django) и **веб-сервер** (Uvicorn, Gunicorn, Nginx):
- **FastAPI** — это прикладной код приложения: он разбирает URL-пути, валидирует данные через Pydantic, вызывает модели LightGBM и формирует JSON-ответ. Но FastAPI **не умеет** самостоятельно открывать TCP-сокеты операционной системы, принимать сетевые пакеты по сети и управлять сетевыми соединениями.
- **Uvicorn** — это специализированный веб-сервер, который слушает указанный порт (например, `:8000`), принимает входящие HTTP/WebSocket запросы от браузеров, передаёт их внутрь приложения FastAPI и отправляет сформированный ответ обратно клиенту.

## 2. Эволюция серверов: от WSGI к ASGI

Чтобы понять, почему FastAPI работает так быстро, нужно знать разницу между двумя стандартами шлюзов в Python:

```
  Клиент (Браузер / Фронтенд)
             │
             ▼ HTTP-запрос
   [ Веб-сервер (Uvicorn) ] ── (Сетевой сокет, TCP, HTTP парсинг)
             │
             ▼ ASGI-интерфейс
   [ Приложение (FastAPI) ] ── (Роуты, Pydantic, LightGBM, Граф знаний)
```

### WSGI (Web Server Gateway Interface) — Прошлое поколение
- Стандарт 2003 года (на нём работают Flask, классический Django, Gunicorn, uWSGI).
- **Синхронная модель:** один рабочий процесс или поток обслуживает ровно один запрос за раз.
- Если запрос ждет ответа от удаленного спутникового сервиса или тяжелой базы данных, поток «засыпает» и простаивает, блокируя все остальные запросы в очереди.

### ASGI (Asynchronous Server Gateway Interface) — Современный стандарт
- Разработан специально для асинхронного Python (`async` / `await`).
- На одном рабочем процессе (одно ядро процессора) сервер может одновременно удерживать **десятки тысяч соединений**, переключаясь между ними в цикле событий (**Event Loop**), пока одни запросы ожидают завершения ввода-вывода (I/O).
- Нативно поддерживает протоколы **HTTP/1.1**, **HTTP/2** и долгоживущие соединения **WebSockets**.

## 3. Что делает Uvicorn молниеносным?

**Uvicorn** — это асинхронный ASGI-сервер, разработанный Томом Кристи (автором Django REST Framework и Starlette). Его невероятная производительность достигается за счет компилируемых компонентов на языке C:
1. **`uvloop`** — быстрая замена стандартного цикла событий Python `asyncio`. Написан на C и базируется на библиотеке `libuv` (высокопроизводительный движок ввода-вывода, на котором работает Node.js).
2. **`httptools`** — C-парсер протокола HTTP, заимствованный напрямую из веб-сервера NodeJS.

В результате Uvicorn обрабатывает сетевые запросы практически со скоростью компилируемых языков (Go или C++).

## 4. Как запускать сервер в нашем проекте?

Сервер запускается из терминала в активированном виртуальном окружении (`.venv`).

### 1. Режим разработки (Development) с автоматической перезагрузкой
```bash
uvicorn water_eutrophication.src.api.main:app --reload --host 0.0.0.0 --port 8000
```

Разбор аргументов команды:
- `water_eutrophication.src.api.main` — путь к Python-модулю (файлу [`src/api/main.py`](file:///home/frolov-pc/antigravity/water_eutrophication/src/api/main.py)).
- `:app` — имя переменной экземпляра `FastAPI()` внутри этого файла (`app = FastAPI(...)`).
- `--reload` — **Hot Reload (горячая перезагрузка)**. Сервер отслеживает изменения во всех файлах `.py`. Как только вы сохраните изменения в коде или добавите новое правило в граф знаний, Uvicorn мгновенно перезагрузит приложение без необходимости останавливать процесс вручную.
- `--host 0.0.0.0` — слушать все сетевые интерфейсы (сервер доступен как с локального компьютера `localhost`, так и по локальной сети университета или внутри Docker-контейнера).
- `--port 8000` — сетевой порт, на котором запускается веб-служба.

### 2. Запуск в продакшне (Production) с несколькими процессами-воркерами
В продакшн-окружении флаг `--reload` **всегда отключается** (он потребляет лишние ресурсы), а вместо одного процесса запускается пул воркеров (`--workers`), равный числу ядер процессора:
```bash
uvicorn water_eutrophication.src.api.main:app --host 0.0.0.0 --port 8000 --workers 4
```
Если сервер имеет 4 ядра, Uvicorn создаст 4 независимых процесса, равномерно распределяя между ними нагрузку от сотен одновременных пользователей.

### 3. Программный запуск прямо из кода Python
Uvicorn можно запускать не только из терминала, но и прямо внутри функции `main()`:
```python
if __name__ == "__main__":
    import uvicorn
    uvicorn.run(
        "water_eutrophication.src.api.main:app",
        host="127.0.0.1",
        port=8000,
        reload=True
    )
```

## 5. Проверка работы сервера через консоль

После старта сервера Uvicorn в терминале появятся строки:
```text
INFO:     Started server process [18452]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
```

Теперь можно протестировать работу эндпоинтов с помощью утилиты `curl`:

```bash
# 1. Проверка доступности корневого эндпоинта
curl http://localhost:8000/

# 2. Получение списка водных объектов Беларуси
curl http://localhost:8000/water-bodies

# 3. Запрос прогноза эвтрофикации для Заславского водохранилища
curl http://localhost:8000/predict/BY_RES_001
```

Каждый запрос мгновенно отображается в логах Uvicorn с указанием IP-клиента, HTTP-метода, пути и статус-кода:
```text
INFO:     127.0.0.1:41234 - "GET /predict/BY_RES_001 HTTP/1.1" 200 OK
```

## 7. Контрольный мини-вопрос для проверки

> **Ситуация:**  
> Разработчик запустил сервис командой:  
> `uvicorn water_eutrophication.src.api.main:app --port 8000` (без флага `--reload`).  
> После этого он открыл файл `main.py`, изменил текст в приветственном сообщении и нажал `Ctrl+S` (сохранить).  
>
> **Вопрос:**  
> Увидят ли пользователи обновлённый текст при следующем запросе `GET http://localhost:8000/`?  
> 1) Да, изменения вступят в силу немедленно.  
> 2) Нет, сервер продолжит отдавать старую версию кода из оперативной памяти до тех пор, пока процесс Uvicorn не будет перезапущен вручную.
